FILES OVERVIEW
================================================================================

1. train_controller.c
   ---------------------
   Main entry point and controller logic.

   State Structure (train_controller_state_t):
   - central_conn, local_conn    : Connection handles
   - mode                        : Local or Global network mode
   - last_recv_*, last_send_*    : Message timestamps
   - ui_needs_update             : Flag to trigger UI refresh
   - mutex                       : Thread synchronization

   Threads:
   - message_handler_thread      : Receives and processes incoming messages
   - connection_thread           : Manages connections to Central and Local
   - ui_refresh_thread           : Refreshes UI only when updates occur
   - heartbeat_thread            : Checks connection health periodically

   Functions:
   - main()                      : Init, thread creation, command loop
   - display_ui()                : Calls train_ui_display()
   - handle_test_message()       : Handler for MSG_TEST messages
   - execute_command()           : Processes user commands (send-central, send-local)


2. ui/train_ui.h
   ---------------------
   Header file defining UI state and API.

   Enums:
   - track_direction_t           : TRACK_UP (W->S), TRACK_DOWN (S->W)
   - track_state_t               : NONE, APPROACHING, ON_CROSSING, CLEARED
   - flash_state_t               : OFF, ON
   - train_frequency_t           : FREQ_PEAK (2 min), FREQ_NIGHT (20 min)
   - train_signal_t              : PROCEED, STOP
   - connection_status_t         : CONNECTED, LOST
   - crossing_fault_t            : NONE, GATE_CLOSE_TIMEOUT, etc.

   Structures:
   - crossing_state_t            : State for one crossing (P1/P2/P3)
   - message_info_t              : Last sent/received message info
   - train_ui_state_t            : Complete UI state with mutex

   Screen Types (ui_screen_t):
   - UI_SCREEN_MENU              : Main menu screen
   - UI_SCREEN_STATUS            : Status display screen
   - UI_SCREEN_COMMAND           : Command input screen

   API Functions:
   - train_ui_init()             : Initialize UI state
   - train_ui_destroy()          : Cleanup mutex
   - train_ui_display()          : Render current screen to terminal
   - train_ui_display_menu()     : Render menu screen
   - train_ui_display_status()   : Render status screen
   - train_ui_display_command()  : Render command screen
   - train_ui_set_screen()       : Change current screen
   - train_ui_get_screen()       : Get current screen
   - train_ui_request_update()   : Mark UI for refresh
   - train_ui_needs_update()     : Check if refresh needed
   - train_ui_set_connection()   : Update connection status (on state change only)
   - train_ui_set_crossing()     : Update full crossing state
   - train_ui_set_track_state()  : Update single track direction
   - train_ui_set_gate_state()   : Update boom gate
   - train_ui_set_crossing_fault(): Update fault status
   - train_ui_set_preempt_time() : Set preempt sent timestamp
   - train_ui_set_clear_time()   : Set clear sent timestamp
   - train_ui_set_frequency()    : Set train frequency mode
   - train_ui_set_signal()       : Set train signal
   - train_ui_set_time_scale()   : Set simulation time scale
   - train_ui_set_last_sent()    : Update last sent message info
   - train_ui_set_last_received(): Update last received message info
   - train_ui_set_active_faults(): Update fault count
   - train_ui_refresh_thread()   : Thread function for periodic UI check


3. ui/train_ui.c
   ---------------------
   UI implementation with terminal display.

   Features:
   - Thread-safe (all setters use mutex)
   - Only repaints when needs_update flag is set
   - ANSI color codes for status highlighting
   - Clear screen before each redraw

   Menu Navigation:
   - Main Menu: Options 1 (Status), 2 (Command), 3 (Exit)
   - Status/Command screens: Press 'q' + Enter to return to menu
   - Auto-refresh only active on Status screen

   Display Layouts:

================================================================================
THREAD SYNCHRONIZATION
================================================================================

- train_controller_state_t.mutex  : Protects controller state
- train_ui_state_t.mutex          : Protects UI state

UI updates only trigger repaint (no continuous refresh):
1. State change occurs
2. Setter function called with new value
3. needs_update flag set to 1
4. ui_refresh_thread detects flag
5. train_ui_display() called, flag cleared
